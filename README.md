# LeadGen Studio — پلتفرم هوشمند لید کسب‌وکارهای محلی

> ساخته‌شده روی اسکیل **`google-maps-scraper`** از مخزن
> [Mahanaicoach/google-maps-scraper-kit](https://github.com/mahanaicoach/google-maps-scraper-kit).
> کیت اصلی «داده خام گوگل‌مپ» می‌دهد؛ این برنامه آن را به **خروجی قابل استفاده برای کسب‌وکار**
> تبدیل می‌کند: لید امتیازدهی‌شده، کانال تماس پیشنهادی، متن کمپین فارسی، داشبورد وب و فایل اکسل.

```
صنف + شهر  →  کلیدواژه‌ها  →  job موتور  →  پاک‌سازی/حذف تکرار  →  غنی‌سازی (ایمیل + شبکه اجتماعی + سیگنال سایت)
           →  امتیازدهی هوشمند ۰-۱۰۰  →  بخش‌بندی داغ/گرم/سرد  →  کمپین فارسی  →  داشبورد + CSV/JSON/XLSX
```

**بدون وابستگی بیرونی:** فقط کتابخانه استاندارد پایتون ۳٫۱۱+ (حتی نوشتن فایل `xlsx` هم بدون
کتابخانه انجام می‌شود). بدون کلید API. همه‌چیز روی دستگاه خودتان.

**✨ وب‌اپ ساده (یک جمله → خروجی):** یک جعبهٔ جست‌وجو، دو ردیف چیپس (هدف و اندازه) و یک دکمه.
صنف، شهر، زبان، کلیدواژه‌ها، عمق، حجم و حتی زمان تقریبی اجرا را **مغز برنامه** تشخیص می‌دهد؛
تنظیمات فنی پشت یک بخش بازشو پنهان‌اند. روی `http://localhost:8000/` اجرا می‌شود و
نسخهٔ نمایشی‌اش (بدون سرور) روی Pages هم کلیک‌خوردنی است: <https://rahmaniho.github.io/Skill/app/>

**🧭 نسخهٔ جمع‌وجور (`mini/`):** یک صفحهٔ کوچک با **یک جعبهٔ جست‌وجو** و چهار انتخابگر آبشاری
**استان ← شهر ← منطقه ← خیابان**. محدوده را تا یک خیابان کوچک می‌کند (شعاع ۹۰۰ متر)،
«همهٔ کسب‌وکارهای منطقه» یا یک صنف خاص را پیدا می‌کند، و با فیلترهای صنف/تماس/امتیاز/ستاره/شعاع
روی همهٔ داده‌های جمع‌شده **جست‌وجوی قوی** می‌کند. روی `http://localhost:8000/mini/` و
نسخهٔ نمایشی‌اش روی <https://rahmaniho.github.io/Skill/mini/>.

**🌐 ویترین و مستندات زنده (بدون نصب، روی GitHub Pages):** <https://rahmaniho.github.io/Skill/>
— لندینگ فارسی + مستندات + کاوشگر لید با داده نمونه، نمودارها، نقشه لوکیشن دقیق و
تولید متن کمپین در همان مرورگر.

## شروع سریع (۲ دقیقه)

```bash
# ۱) وب‌اپ بالا می‌آید (بدون داکر هم کار می‌کند)
python3 -m leadgen.server          # یا: ./run.sh
#   → http://localhost:8000/          وب‌اپ ساده: فقط یک جمله بنویسید
#   → http://localhost:8000/mini/     نسخهٔ جمع‌وجور: استان/شهر/منطقه/خیابان
#   → http://localhost:8000/studio/   داشبورد حرفه‌ای با همهٔ تنظیمات

# ۱ب) دادهٔ نمونهٔ منطقه‌محور برای گشت‌وگذار در رابط‌ها (۷ اجرا در ۵ محدوده، بدون داکر)
./run.sh seed --fresh

# ۲) یا از ترمینال خروجی فایل بگیرید
python3 -m leadgen.cli run "دندانپزشکی" --city "تهران" --profile web_design --socials

# ۲ب) جست‌وجوی «تمامی مشاگل» یک شهر با کارت تماس کامل + لوکیشن دقیق
python3 -m leadgen.cli run --all-niches --city "تهران" --lang fa \
  --max-niches 12 --keywords-per-niche 2 --cols contact --export xlsx

# ۲پ) فقط یک منطقه/خیابان خاص (منطقه و خیابان از جدول داخلی ۲۵۰+ منطقه و ۱۳۰+ خیابان)
python3 -m leadgen.cli run --all-niches --city "تهران" --district "ونک" \
  --street "خیابان ملاصدرا" --lang fa --cols contact --export xlsx

# ۳) برای داده واقعی گوگل‌مپ (نه نمونه):
docker compose up -d          # موتور روی localhost:8080
python3 -m leadgen.cli doctor # باید بنویسد: موتور فعال = docker (واقعی)
```

> **داکر ندارید؟** برنامه با **موتور دمو** کامل کار می‌کند: همان پایپ‌لاین، همان خروجی‌ها،
> با داده نمونه واقع‌نما برای هر صنف و هر شهر. برای دیدن تمام قابلیت‌ها کافی است.

## چه چیزی به‌دست می‌آورید

### ۱) فایل خروجی (برای فروش و بازاریابی)
| فایل | محتوا |
|---|---|
| `xlsx` چند برگی | **لیدها** · **لیدهای داغ** · **خلاصه** · **شکاف‌های دیجیتال** · **قیف** · **بینش‌ها** · **کمپین** (RTL، فیلتر خودکار) |
| `csv` با BOM | ستون‌های فارسی، مستقیم در اکسل/گوگل‌شیت باز می‌شود |
| `csv` کمپین | نام، کانال، گیرنده، موضوع، **متن آماده ارسال** |
| `json` | کل اجرا + آمار + لیدها (برای اتصال به CRM/ابزار دیگر) |

**۴ پیش‌تنظیم ستون** — هر جا خروجی می‌گیرید (CLI: `--cols`، API: `?cols=`، داشبورد: کشوی «ستون‌ها»):

| پیش‌تنظیم | ستون‌ها | برای چه کاری |
|---|---|---|
| `lead` | ۸ فیلد اصلی اسکیل + غنی‌سازی + امتیاز/بخش/کانال | پیش‌فرض؛ فهرست کاری تیم فروش |
| `contact` | **کارت تماس کامل**: نام، صنف منبع، دسته گوگل، شهر، نشانی، تلفن، ایمیل، همه ایمیل‌ها، سایت، IG/FB/LinkedIn، **لوکیشن دقیق، lat، lon، لینک نقشه گوگل، پلاس‌کد**، امتیاز گوگل، تعداد نظر، کامل بودن ٪، امتیاز لید، بخش، کانال، زاویه، شکاف‌ها، برچسب‌ها، وضعیت، یادداشت | تماس و ویزیت؛ همان چیزی که خواسته شد |
| `location` | نام، تماس، نشانی + همه فیلدهای مکانی | کار میدانی، مسیربندی ویزیتور |
| `all` | هر ۳۴ ستون خام موتور + همه فیلدهای محاسبه‌شده | تحلیل/بایگانی کامل |

فایل کنارِ `*-leads.csv` همیشه با پیش‌تنظیم `contact` نوشته می‌شود تا بدون تنظیم اضافه
قابل استفاده باشد.

**لوکیشن دقیق هر کسب‌وکار** در همه خروجی‌ها هست: `latitude`/`longitude` (و `lat`/`lon` عددی)،
رشتهٔ `location`، `plus_code`، و `maps_link` — که اگر لینک خودِ مکان در داده موتور باشد همان،
وگرنه `https://www.google.com/maps/search/?api=1&query=lat,lon` و در نهایت جست‌وجوی
نام + نشانی استفاده می‌شود. «کامل بودن اطلاعات» هم حالا از ۶ کانال حساب می‌شود:
سایت، ایمیل، تلفن، شبکه اجتماعی، **لوکیشن**، نشانی.

### ۲) وب‌اپ ساده — یک جمله تا خروجی (`smart/`)
روی `http://localhost:8000/` باز می‌شود. طراحی‌شده برای کسی که **نمی‌خواهد** با عمق و grid و
پروفایل امتیازدهی درگیر شود:

| روی صفحه | چه می‌کند |
|---|---|
| یک جعبهٔ جست‌وجو | «دندانپزشکی در تهران»، «همه مشاغل در مشهد»، «کافه و رستوران در اصفهان»، `plumbers in Denver CO` |
| پیشنهاد زنده | همزمان با تایپ، صنف/شهر/گروه شغلی پیشنهاد می‌دهد (فارسی و انگلیسی) |
| چیپس «هدفت چیست؟» | سایت می‌فروشم · تبلیغات/سئو · کالا به کسب‌وکارها · جذب نیرو · فقط فهرست تمیز → **پروفایل امتیازدهی** را می‌چیند |
| چیپس «چقدر بزرگ؟» | سریع (۶۰ لید، depth ۲) · استاندارد (۲۰۰ لید) · کامل/کل شهر (grid ۳×۳، بدون سقف) |
| کارت «مغز چه فهمید» | صنف، شهر، زبان، تعداد کلیدواژه، **زمان تقریبی اجرا** و خودِ کلیدواژه‌ها + هشدارها (مثلاً «شهر پیدا نشد → تهران گذاشتم») |
| پیشرفت زنده | نوار درصد + گزارش مرحله‌ای |
| نتایج | KPIها، بینش‌ها، سه نمودار (پوشش تماس، بخش‌بندی، شکاف‌ها)، کارت/جدول لیدها با **حلقهٔ امتیاز**، فیلتر داغ/گرم/سرد، جست‌وجو، مرتب‌سازی، صفحه‌بندی |
| پروندهٔ لید | اطلاعات + **لوکیشن دقیق و لینک نقشه** + «چرا این امتیاز؟» (عامل‌به‌عامل) + متن آمادهٔ ارسال در ۵ کانال + وضعیت پیگیری |
| خروجی | اکسل / CSV / JSON / فایل کمپین / فقط داغ‌ها — با همان پیش‌تنظیم ستون‌ها |

```
جملهٔ شما → smart.parse() → {صنف، شهر، زبان، حالت (تک‌صنفی/جارو)، کلیدواژه‌ها، حجم، زمان تقریبی}
         → همان request که CLI می‌سازد → POST /api/runs → پایپ‌لاین ۹ مرحله‌ای → نتایج
```

> **بدون سرور هم کار می‌کند:** اگر `/api/health` پاسخ ندهد، وب‌اپ خودش به **حالت دمو** می‌رود
> (همان دادهٔ نمونهٔ Pages) و همه‌چیز — جست‌وجو، اجرا، کمپین، خروجی — داخل مرورگر انجام می‌شود.
> به همین دلیل نسخهٔ Pages آن در <https://rahmaniho.github.io/Skill/app/> زنده است.

### ۳) نسخهٔ جمع‌وجور — استان ← شهر ← منطقه ← خیابان (`mini/`)
روی `http://localhost:8000/mini/` باز می‌شود؛ یک صفحه، بدون منو و بدون تب:

| روی صفحه | چه می‌کند |
|---|---|
| یک جعبهٔ جست‌وجو | «کافه در ونک تهران»، «همهٔ کسب‌وکارهای چیتگر»، `restaurants in Tehran Vanak` — صنف **و** منطقه/خیابان از خود جمله بیرون کشیده می‌شود |
| پیشنهاد زنده | همزمان با تایپ، منطقه/خیابان/شهر/صنف پیشنهاد می‌دهد (فارسی، انگلیسی و فینگلیش)؛ یک کلیک = پر شدن انتخابگرها |
| چهار انتخابگر آبشاری | **استان/کشور** (۳۱ استان + ۲۲ کشور) ← **شهر** (۱۶۳ شهر، ۱۱۷ ایرانی) ← **منطقه** (۲۵۰+) ← **خیابان** (۱۳۰+) — هر سطح مختصات، شعاع و زوم خودش را دارد |
| «همهٔ کسب‌وکارهای این محدوده» | جاروی چندصنفی فقط در همان محدوده، یا یک صنف مشخص از کشوی ۹۱ صنفی |
| نوار محدوده | برچسب خوانا (`تهران، ونک، خیابان ملاصدرا`)، سطح، شعاع، `lat/lon` و لینک نقشه |
| فیلترها | داغ/گرم/سرد · تلفن · ایمیل · وب‌سایت · اینستاگرام · شبکه اجتماعی · **بدون سایت** · **صنف (از دل نتایج)** · حداقل امتیاز/ستاره/تعداد نظر · وضعیت پیگیری · مرتب‌سازی · **جست‌وجو در نتایج** |
| «فقط داخل محدودهٔ انتخابی» | فیلتر شعاع دایره‌ای (هاورسین) حول منطقه/خیابان انتخابی — روی **همهٔ اجراهای قبلی** |
| 📚 داده‌های قبلی | **جست‌وجوی قوی**: همان عبارت (چند کلمه‌ای، AND) روی تمام لیدهای جمع‌شده در پایگاه‌داده، با `facets` زنده برای هر فیلتر |
| نتایج | جدول متراکم: نام، صنف، منطقه/نشانی، فاصله، تلفن، ایمیل، سایت، شبکه‌ها، ★، تعداد نظر، امتیاز، بخش، وضعیت + صفحه‌بندی |
| پروندهٔ لید | تماس/ایمیل/سایت/شبکه‌ها، **لوکیشن دقیق** و لینک نقشه، واتساپ، شکاف‌ها، زاویهٔ فروش، **متن آمادهٔ تماس در ۵ کانال**، تغییر وضعیت + یادداشت |
| خروجی | CSV / XLSX / JSON از **همان مجموعهٔ فیلترشده** (می‌تواند چند اجرا را شامل شود) با ۴ پیش‌تنظیم ستون |

```
انتخابگرها/جمله → smart.parse() → regions.resolve() → {نقطه، شعاع، زوم، برچسب، bbox}
                → POST /api/runs (اجرایی دقیقاً روی همان محدوده) → /api/search (فیلترها + facets)
```

> **چطور محدوده اعمال می‌شود؟** `regions.resolve()` نقطه و شعاع سطح را می‌دهد
> (خیابان ۹۰۰ م · منطقه ۲۵۰۰ م · شهر ۱۰۰۰۰ م · استان ۳۰۰۰۰ م)، `pipeline.apply_area()`
> همان را روی درخواست می‌نشاند، کلیدواژه‌ها نام دقیق منطقه/خیابان را می‌گیرند
> (`کافه در خیابان ملاصدرا، ونک، تهران`) و در سطح خیابان/منطقه یک `bbox` تنگ هم
> اضافه می‌شود تا ردیفهای پرت حذف شوند. در سطح استان `bbox` گذاشته نمی‌شود تا بقیهٔ
> شهرهای استان حذف نشوند.

> **بدون سرور هم کار می‌کند:** اگر سرور محلی در دسترس نباشد، همان رابط به حالت نمونه می‌رود:
> درخت استان/شهر/منطقه/خیابان، فهرست نام‌ها (فارسی و لاتین) و ۱۵۰ لید نمونه از
> `site/data/sample.json` خوانده می‌شود و جست‌وجو/فیلتر/شعاع/خروجی داخل مرورگر انجام می‌شود.
> به همین دلیل <https://rahmaniho.github.io/Skill/mini/> بدون هیچ سروری زنده است.

### ۴) داشبورد حرفه‌ای فارسی (RTL) — `/studio/`
- **اسکراپ جدید**: انتخاب صنف (۹۱ صنف آماده + هر صنف دلخواه)، شهر، پیش‌نمایش کلیدواژه‌ها، عمق،
  شبکه (grid) برای پوشش کل شهر، پروفایل امتیازدهی، غنی‌سازی، قالب خروجی و **پیش‌تنظیم ستون‌ها**.
- **کلید «جست‌وجوی تمامی مشاغل»**: جاروی چندصنفی با انتخاب گروه‌ها (چیپ‌های ۱۳ دسته)،
  سقف تعداد صنف و کلیدواژه به ازای هر صنف — با هشدار اندازه اجرا و پیشنهاد پراکسی.
- **پیشرفت زنده** با درصد، گزارش مرحله‌ای و هشدارها (برای جارو، پیشرفت هر job جدا نشان داده می‌شود).
- **لیدها**: فیلتر بخش/وضعیت/کانال/شکاف، جست‌وجو، مرتب‌سازی، صفحه‌بندی، ستون **📍 نقشه**،
  کشوی جزئیات با **لوکیشن دقیق**، **صنف منبع**، **تحلیل عامل‌به‌عامل امتیاز**، لینک مستقیم
  واتس‌اپ/ایمیل، و تغییر وضعیت پیگیری (مینی‌CRM).
- **تحلیل**: بینش‌های اجرایی، قیف لید، دونات بخش‌بندی، پوشش تماس، شکاف‌های دیجیتال، توزیع امتیاز،
  توزیع رتبه گوگل، **نقشه پراکندگی آفلاین**، بهترین کانال، عملکرد کلیدواژه‌ها.
- **کمپین**: متن آماده ارسال با اطلاعات فرستنده شما، دنباله ۳ لمسی ایمیل، کپی با یک کلیک.
- **ورود داده**: فایل CSV/JSON موجود خودتان را بدهید → امتیازدهی + کمپین (بدون اسکراپ).

### ۵) CLI
```bash
python3 -m leadgen.cli doctor                 # سلامت محیط: موتور، داکر، پایگاه‌داده
python3 -m leadgen.cli niches                 # فهرست اصناف

python3 -m leadgen.cli cities                 # ۱۶۳ شهر داخلی (آفلاین)
python3 -m leadgen.cli areas --provinces      # ۳۱ استان + مرکز و تعداد شهرها
python3 -m leadgen.cli areas --city "تهران"    # ۱۲۹ منطقه/محله با مختصات
python3 -m leadgen.cli areas --city tehran --streets --district "منطقه ۳"
python3 -m leadgen.cli profiles               # پروفایل‌های امتیازدهی و وزن‌ها

python3 -m leadgen.cli run "رستوران" --city "تهران" --lang fa --grid 3 --socials
python3 -m leadgen.cli run "plumbers" --city "Denver, CO" --depth 8 --profile web_design
python3 -m leadgen.cli run "کافه" --city "دبی" --keyword "کافه در دبی" --export csv
python3 -m leadgen.cli run "کافه" --city "تهران" --district "ونک" --street "خیابان ملاصدرا" \
  --lang fa --all-niches --cols contact      # فقط همان خیابان، شعاع ۹۰۰ متر

# جست‌وجوی قوی در همهٔ داده‌های جمع‌شده (همهٔ اجراها) + خروجی از همان مجموعهٔ فیلترشده
python3 -m leadgen.cli search "کافه" --has-email 1 --min-score 70 --limit 20
python3 -m leadgen.cli search --city "تهران" --district "ونک" --segment hot   # شعاع خودکار ۲۵۰۰ متر
python3 -m leadgen.cli search --street "خیابان ملاصدرا" --city "تهران" --has-website 0 --export xlsx

python3 -m leadgen.cli runs                   # فهرست اجراها
python3 -m leadgen.cli leads <run-id> --segment hot --limit 20
python3 -m leadgen.cli export <run-id> --fmt xlsx --segment hot --cols contact
python3 -m leadgen.cli campaign <run-id> --channel whatsapp --out messages.csv
python3 -m leadgen.cli score-file my-leads.csv --profile marketing   # فهرست موجود شما
python3 -m leadgen.cli rescore <run-id> --profile b2b_supply         # بدون اسکراپ دوباره
```

کلیدهای پرکاربرد `run`:

| کلید | کار |
|---|---|
| `--cols {lead,contact,location,all}` | پیش‌تنظیم ستون‌های خروجی (پیش‌فرض `lead`) |
| `--full` | همه ستون‌ها (معادل `--cols all`) |
| `--all-niches` | جاروی «تمامی مشاگل» یک شهر |
| `--groups "دسته۱,دسته۲"` | محدود کردن جارو به دسته‌های مشخص |
| `--max-niches N` | سقف تعداد صنف در جارو (پیش‌فرض ۱۲) |
| `--keywords-per-niche N` | کلیدواژه به ازای هر صنف در جارو (پیش‌فرض ۲) |
| `--keywords-per-job N` | کلیدواژه در هر job (پیش‌فرض ۸) |
| `--province` / `--district` / `--street` | محدود کردن به استان/منطقه/خیابان (شعاع و زوم خودکار؛ در سطح خیابان/منطقه `grid` خاموش و `bbox` تنگ می‌شود) |
| `--grid N` | کاشی‌بندی n×n برای پوشش کل شهر (در جارو و در سطح منطقه/خیابان خاموش است) |
| `--socials` / `--no-email` / `--no-deep-emails` | کنترل غنی‌سازی |
| `--engine {auto,docker,demo}` | موتور اجرا |

کلیدهای `search` (جست‌وجوی قوی): `--run` `--city/--province/--district/--street` `--radius-m`
`--segment` `--status` `--niche-id/--group` `--has-phone/--has-email/--has-website/--has-social/--has-instagram`
(هرکدام `1` یا `0`) `--min-rating/--min-reviews/--min-score` `--sort/--order` `--limit/--offset`
`--export {csv,json,xlsx} --out <path> --cols <preset>`.

## لایه هوشمند

### مغز جمله‌فهم (`leadgen/smart.py`)
همان چیزی که اجازه می‌دهد وب‌اپ ساده فقط **یک جعبهٔ جست‌وجو** داشته باشد. جملهٔ آزاد را می‌گیرد و
به یک درخواست دقیقِ اجرا تبدیل می‌کند:

| ورودی | تصمیم مغز |
|---|---|
| «دندانپزشکی در تهران» | تک‌صنفی · صنف `دندانپزشکی` · شهر تهران · زبان `fa` · کلیدواژه‌ها با شهر درونشان |
| «همه مشاغل در مشهد» | **جاروی تمامی مشاغل** · ۶ صنف چرخشی از ۶ دسته · `all_niches` · grid خاموش |
| «کافه و رستوران در اصفهان» | دو صنف نام برده → جاروی همان دسته («غذا و نوشیدنی») |
| «خدمات فنی و ساختمان در شیراز» | فقط نام دسته → جارو **محدود به همان دسته** (لوله‌کشی، برق‌کاری، پکیج، ایزوگام…) |
| `plumbers in Denver CO` | زبان `en` · صنف `plumber` · شهر Denver (آفلاین) |
| «آرایشگاه» (بدون شهر) | اجرا می‌شود، ولی شهر پیش‌فرض می‌گذارد و **هشدار + نیاز به تأیید** برمی‌گرداند |
| «» (خالی) | `ready=false` و `missing=["niche"]` — هرگز صنفی را از خودشان القا نمی‌کند |

خروجی `parse()` شامل `mode` (`empty|single|sweep`)، `detected`، `keywords`، `eta_minutes`
(بازهٔ زمان بر پایهٔ تعداد کلیدواژه × عمق × کاشی‌ها ÷ توان موتور)، `summary` فارسی،
`warnings`، `needs_confirmation` و `request` است — همان بدنه‌ای که مستقیماً به
`POST /api/runs` می‌رود. تشخیص شهر طوری نوشته شده که **فقط بازهٔ نام شهر** را جدا کند
(نه کل جمله را)، وگرنه «کلینیک زیبایی تهران» به شهر «تهران» با صنف خالی تجزیه می‌شد.

### امتیازدهی بر اساس «هدف کسب‌وکار شما»
امتیاز ۰-۱۰۰ با روبریک شفاف و قابل توضیح (بدون جعبه سیاه). وزن‌ها به پروفایل شما وابسته است:

| پروفایل | برای چه کسی | عامل غالب |
|---|---|---|
| `web_design` | فروش سایت/فروشگاه | **شکاف دیجیتال** (کسب‌وکار بدون سایت = داغ‌ترین) |
| `marketing` | تبلیغات، سئو، اینستاگرام | شکاف دیجیتال + فعالیت (نظرات کم = فرصت) |
| `b2b_supply` | فروش کالا/تجهیزات به کسب‌وکارها | **دسترس‌پذیری** + اعتبار |
| `recruitment` | جذب نیرو/همکار | فعالیت + دسترس‌پذیری |
| `generic` | حالت متوازن | — |

پنج عامل: **شکاف دیجیتال**، **دسترس‌پذیری**، **اعتبار و کیفیت**، **فعالیت و حجم مشتری**،
**تناسب با صنف**. برای هر لید می‌بینید هر عامل چند امتیاز آورده و چرا.

خروجی امتیازدهی: `score`، `segment` (داغ/گرم/سرد)، `gaps` (بدون وب‌سایت، بدون رزرو آنلاین،
نظرات کم، …)، `tags`، `channel` (ایمیل ← دایرکت اینستاگرام ← واتس‌اپ ← تماس ← فرم سایت)،
`pitch` (یک جمله زاویه ورود).

### غنی‌سازی با **صفر توکن LLM**
همه با HTTP + regex در کد انجام می‌شود (نه با خواندن صفحه‌ها در context یک مدل):
- **پاس عمیق ایمیل**: صفحه اصلی و تا ۳ صفحه «تماس/درباره»؛ حذف ایمیل‌های هرزنامه
  (`wix`, `sentry`, `example`, …) و اولویت دادن به ایمیل هم‌دامنه.
- **شبکه‌های اجتماعی**: Instagram / Facebook / LinkedIn با فیلتر هندل‌های بی‌ارزش
  (`/sharer`, `/explore`, `/p`, …). پوشش واقعی ~۴۰-۷۰٪ است (فقط کسانی که در سایتشان لینک دارند).
- **سیگنال‌های سایت**: واتس‌اپ، تلگرام، رزرو/نوبت‌دهی، سفارش آنلاین، فرم تماس، وردپرس/ویکس/
  شاپیفای، گوگل‌آنالیتیکس، چت آنلاین — اینها هم در امتیاز و هم در انتخاب زاویه کمپین استفاده می‌شوند.
- **نرمال‌سازی**: تلفن به فرمت بین‌المللی (تشخیص موبایل ایران)، دامنه، ایمیل یکتا، اعداد.

### کمپین فارسی آماده ارسال
- ایمیل: دنباله ۳ لمسی (روز ۰ / ۳ / ۸) با موضوع و متن شخصی‌سازی‌شده.
- واتس‌اپ و پیامک (زیر ۲۸۰ نویسه) و دایرکت اینستاگرام (دو قدمی) و سناریوی تماس تلفنی.
- نسخه انگلیسی برای بازارهای خارج (`language=en`).
- در هر متن، **هویت فرستنده و گزینه «لغو دریافت»** نگه داشته می‌شود.

### همه اصناف
۹۱ صنف آماده در ۱۳ دسته (سلامت، زیبایی، غذا، خدمات فنی و ساختمان، خودرو، حقوقی/مالی، آموزش و ورزش،
رویداد و رسانه، خرده‌فروشی، سفر و اقامت، فناوری و خدمات حرفه‌ای، صنعت و B2B، خدمات محلی).
هر صنف شامل کلیدواژه‌های فارسی و انگلیسی، شعاع/عمق پیشنهادی، سطح نیاز دیجیتال، نقاط درد و
قلاب‌های فروش است. اگر صنفی پیدا نشود، **صنف سفارشی** از همان عبارت شما ساخته می‌شود —
پس هیچ صنفی بیرون نمی‌ماند.

### جست‌وجوی تمامی مشاغل (جاروی چندصنفی)
به‌جای یک صنف، کل بازار یک شهر را جارو می‌کند — برای وقتی که می‌خواهید «همه کسب‌وکارها» را
در یک فایل داشته باشید:

- **نوبت‌دهی گردشی بین ۱۳ دسته**: `niches.sweep_plan()` از هر دسته به‌نوبت برمی‌دارد، پس نتیجه
  هرگز تک‌دسته نمی‌شود (مثلاً ۶ صنف → ۶ دسته متفاوت). با `--groups` می‌توانید به چند دسته
  محدود کنید: `"سلامت و پزشکی,غذا و نوشیدنی"`.
- **jobهای متوالی**: کلیدواژه‌ها به jobهای ≤ `--keywords-per-job` تقسیم می‌شوند و **یکی‌یکی**
  اجرا می‌شوند (قاعده اسکیل: هر بار یک job) تا نرخ‌محدود نشوید.
- **یکتاسازی بین صنف‌ها**: همان کسب‌وکار که در دو کلیدواژه آمده، یک بار می‌ماند (`place_id` ← `cid` ← `link` ← نام+نشانی).
- **تگ «صنف منبع»**: هر ردیف `niche_id`/`niche_fa` و کلیدواژه منبع (`input_id`) را نگه می‌دارد،
  پس در خروجی می‌دانید هر لید از کدام جست‌وجو آمده.
- **`limit` بعد از امتیازدهی**: سقف نتیجه روی **بهترین** لیدها اعمال می‌شود، نه اولین‌ها
  (با یک سقف موقت پیش از غنی‌سازی تا هزینه غنی‌سازی منفجر نشود — در صورت عبور، هشدار می‌دهد).
- **هشدار، نه توقف**: اندازه اجرا، پیشنهاد پراکسی و تداخل `grid` با جارو فقط هشدار می‌دهند.
  در حالت جارو، `grid` خاموش می‌ماند چون تعداد jobها ضرب می‌شد.

```bash
python3 -m leadgen.cli run --all-niches --city "تهران" --lang fa --max-niches 12 \
  --keywords-per-niche 2 --keywords-per-job 8 --cols contact --limit 400
python3 -m leadgen.cli run --all-niches --city "مشهد" --groups "خدمات فنی و ساختمان,خودرو" --engine demo
```

### جغرافیای منطقه‌ای (`leadgen/regions.py`)
- **۳۱ استان** با مرکز و مختصات، **۱۶۳ شهر** (۱۱۷ شهر ایرانی، همهٔ مراکز استان) با `bbox`،
  **۲۵۰+ منطقه/محله** و **۱۳۰+ خیابان** با مختصات آماده — همه آفلاین.
- `resolve(province, city, district, street)` → نقطه، سطح، شعاع، زوم و دو برچسب
  (نمایشی «کلی ← جزئی» و کلیدواژه «جزئی ← کلی»).
- `detect_area(text)` نام منطقه/خیابان را **داخل جملهٔ آزاد** پیدا می‌کند؛ تطبیق روی
  ۱۰۰۰+ شکل نرمال‌شده از نام‌ها انجام می‌شود: با/بی‌نیم‌فاصله، با/بی‌پیشوند
  («خیابان ونک» و «ونک»)، نام‌های لاتین و فینگلیش (`Vanak`، `Saadat Abad`، `Hemmat Highway`)،
  و اولویت سطح جزئی‌تر وقتی کاربر نام کامل را نوشته است.
- شهرهای خارج از ایران زیر «سایر کشورها» گروه‌بندی می‌شوند (۲۲ کشور، ~۴۶ شهر).

### شهرها و پوشش کامل شهر
- ۱۶۳ شهر داخلی با مختصات و محدوده (آفلاین، بدون درخواست شبکه) + هر شهر دیگر از Nominatim.
- حالت **شبکه (grid)**: شهر را به n×n کاشی تقسیم می‌کند و کاشی‌ها را **پشت‌سرهم** اجرا می‌کند
  تا سقف ~۱۲۰ نتیجه در هر جست‌وجوی گوگل شکسته شود؛ سپس بر اساس `place_id` یکتا می‌کند و
  ردیف‌های بیرون از محدوده شهر را دور می‌ریزد.

  server.py         سرور HTTP + API + سرو فایل‌های استاتیک هر سه رابط
  cli.py            رابط خط فرمان
smart/              وب‌اپ ساده (یک جمله → خروجی) روی `/`؛ HTML/CSS/JS خالص + حالت دمو بدون سرور
  app.js            لایهٔ live/demo، رندر نتایج، پروندهٔ لید، کمپین، خروجی
  campaign.js       قالب‌های کمپین در مرورگر (فقط برای حالت دمو؛ آینهٔ campaign.py)
mini/             نسخهٔ جمع‌وجور روی `/mini/`: جست‌وجو + استان/شهر/منطقه/خیابان + فیلترها
  app.js            لایهٔ live/demo، آبشار انتخابگرها، جست‌وجوی قوی، جدول، پروندهٔ لید، خروجی
web/                داشبورد حرفه‌ای فارسی RTL روی `/studio/` (بدون CDN)
site/               نسخه قابل انتشار روی GitHub Pages (لندینگ + مستندات + دموی آفلاین)
  app/              کپی وب‌اپ ساده در حالت دمو → https://rahmaniho.github.io/Skill/app/
  mini/             کپی نسخهٔ جمع‌وجور در حالت دمو → https://rahmaniho.github.io/Skill/mini/
  data/sample.json  داده نمونه مصنوعی + بستهٔ `mini` (درخت منطقه‌ها و فهرست نام‌ها)
scripts/            ساخت دادهٔ نمونه، دادهٔ منطقه‌محور توسعه، کپی رابط‌ها برای Pages، تست دود سه صفحه (DOM ساختگی)
tests/              ۱۷۴ تست (پایپ‌لاین، جارو، لوکیشن، ستون‌ها، API، سایت، مغز جمله‌فهم، **منطقه‌ها و جست‌وجوی قوی**)
.github/workflows/  CI (تست‌ها + smoke سه صفحه + هم‌خوانی Pages) و استقرار خودکار Pages

رفتار پروفایل‌های امتیازدهی، دنباله کمپین، نویسنده XLSX، **پیش‌تنظیم‌های ستون در CSV/XLSX**،

(ساده، grid و **جارو**)، CLI، ورود فهرست موجود، همه مسیرهای HTTP، **یکپارچگی دادهٔ سایت Pages**،
**منطقه‌ها و جست‌وجوی قوی** (`tests/test_regions.py`): ساختار درخت استان/شهر، سالم بودن
`bbox` همهٔ شهرها، نام فارسی همهٔ شهرهای ایرانی، تشخیص منطقه/خیابان از جملهٔ فارسی و لاتین،
ترجیح «خیابان ونک» بر «ونک» و برعکس، سطح/شعاع/زوم/برچسب‌های `resolve`، `apply_area`
(شعاع و `bbox` و بی‌اثر بودن فراخوانی دوم و حفظ `grid` وقتی منطقه‌ای انتخاب نشده)،
`search_leads` (AND بین توکن‌ها، فیلترهای تماس/کیفیت، **فیلتر صنف**، **شعاع دایره‌ای**، facets، صفحه‌بندی)،
مسیرهای `/api/regions*`، `/api/search`، `/api/search/export` و سرو شدن `/mini/`؛
و **مغز جمله‌فهم** (`tests/test_smart.py`): تشخیص صنف/شهر/زبان، تک‌صنفی در برابر جارو،
جاروی محدود به یک گروه، جملهٔ خالی (که نباید صنف پیش‌فرض القا کند)، هشدار شهرِ پیدا‌نشده،
زمان تقریبی، `POST /api/smart/*`، و اجرای سربه‌سر از جملهٔ کاربر تا لیدِ دارای `lat/lon`.

در CI (`.github/workflows/ci.yml`) روی پایتون ۳٫۱۱ و ۳٫۱۲ اجرا می‌شود: compile check،

## محدودیت‌ها و رعایت قانون

- **نرخ‌محدود شدن گوگل:** اجرای سنگین یا پشت‌سرهم بدون پراکسی می‌تواند IP شما را موقتاً محدود
  کند (دقیقه تا ساعت؛ jobها `failed` یا خالی برمی‌گردند). برنامه **هشدار می‌دهد ولی متوقف نمی‌کند**.
  نشانه‌ها: job ناموفق، نتیجه خالی/کوتاه، افت ناگهانی تعداد ردیف. راه‌حل: مکث، کاهش `depth`، پراکسی.
- **سقف نتایج:** هر جست‌وجوی گوگل حدود ۱۲۰ نتیجه می‌دهد؛ برای کل شهر از `--grid 3` استفاده کنید.
- **شبکه‌های اجتماعی:** گوگل‌مپ لینک اجتماعی ندارد؛ ما از سایت کسب‌وکار استخراج می‌کنیم →
  پوشش جزئی است و کسب‌وکار بدون سایت، اجتماعی هم ندارد.
- **داده شخصی:** ایمیل و تلفن داده شخصی‌اند. برای ذخیره یا تماس، GDPR / CCPA / CAN-SPAM را
  رعایت کنید (مبنای قانونی، هویت فرستنده، گزینه انصراف، فهرست سرکوب).
- **شرایط استفاده گوگل:** اسکراپ گوگل‌مپ با ToS گوگل هم‌خوانی ندارد. حجم را متعادل نگه دارید،
  خروجی را «لید نیازمند تأیید» بدانید، داده خام را نفروشید.
- **مجاز نیست:** نظارت بر افراد، اسپم، آزار.
- **امنیت:** موتور کیت احراز هویت ندارد و باید روی `127.0.0.1` بماند. اگر این داشبورد را بیرون از
  دستگاه منتشر می‌کنید، پشت پراکسی احراز هویت بگذارید. `data/` در `.gitignore` است — هرگز commit نشود.

## رفع اشکال

| نشانه | راه‌حل |
|---|---|
| `422 missing max time` / `missing geo coordinates` | برنامه خودش پر می‌کند؛ اگر دستی API می‌زنید `max_time` (ثانیه) و `lat`/`lon` (رشته) لازم است |
| job روی `working` گیر کرده | `depth` کمتر، `max_time` بیشتر، یا IP محدود شده (پراکسی/صبر) |
| CSV خالی | کلیدواژه خیلی باریک یا مختصات اشتباه — `radius` را بیشتر کنید |
| `Connection refused` روی ۸۰۸۰ | `docker compose up -d` |
| داشبورد «موتور دمو» نشان می‌دهد | طبیعی بدون داکر؛ برای داده واقعی موتور را بالا بیاورید |
| فارسی در اکسل به‌هم ریخته | خروجی CSV با BOM نوشته می‌شود؛ اگر باز هم خراب بود از `xlsx` استفاده کنید |
